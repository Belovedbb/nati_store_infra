# Nati Store infrastructure

TypeScript deployment for one AWS Lightsail server. CloudFormation manages the Lightsail foundation. SSH and Docker Compose manage three units on that server: Docker setup (`server`), PostgreSQL (`postgres`), and the backend, storefront, and Caddy proxy (`app`). Each unit can run independently or in order with `--all`.

## Configuration

Edit `environments/dev.ts` or `environments/prod.ts`. Each environment maps to the `nati-store-deployer` AWS profile and a Secrets Manager secret ID. Set the Lightsail settings, your public SSH CIDR (usually `your-ip/32`), container limits, image references, and real store/API domains. Changing an existing instance's bundle or blueprint requires a replacement or migration plan.

Keep secrets out of the repository. Create a Secrets Manager secret named `nati-store/dev/app` or `nati-store/prod/app` in the configured region with this JSON value:

```json
{
  "postgresPassword": "replace-me",
  "jwtSecret": "replace-me",
  "cookieSecret": "replace-me",
  "medusaPublishableKey": "replace-me"
}
```

PostgreSQL deployment needs only `postgresPassword`; app deployment needs all four. The publishable key is generated by Medusa and is not private, but the current storefront deployment reads it from the same configuration bundle. The first-run creation and handoff still need automation.

The only remaining local deployment credential is:

| Variable | Used by |
| --- | --- |
| `NATI_SSH_KEY_PATH` | Lightsail SSH private key |

Verify the instance SSH host fingerprint and add it to local `known_hosts` before deploying host units. The configured instance user defaults to `ubuntu`.

## Commands

Use Node.js 22+ and pnpm 10.11.1. AWS credentials use the standard SDK credential chain. The CLI sets `AWS_PROFILE` from the selected environment when it is absent and rejects a different explicit `AWS_PROFILE`. Credentials already exported by awsume are used by the SDK, so assume the matching profile in the same shell before running the commands. The assumed role needs CloudFormation, Lightsail, and `secretsmanager:GetSecretValue` access.

```bash
pnpm install
pnpm typecheck
awsume nati-store-deployer   # optional; not needed with static keys in ~/.aws/credentials
pnpm diff dev --stack foundation
pnpm run deploy dev --stack foundation
pnpm run deploy dev --stack server
pnpm run deploy dev --stack postgres
pnpm run deploy dev --stack app
pnpm diff dev --all
pnpm run deploy dev --all
```

Replace `dev` with `prod` as needed. `--stack` accepts `foundation`, `server`, `postgres`, or `app`. `--all` runs them in that order. Host units require the foundation and working SSH access. PostgreSQL and app require the Docker setup; app also requires healthy PostgreSQL.

For `foundation`, `diff` previews a CloudFormation change set and `deploy` executes one. For host units, `diff` compares a configuration fingerprint and prints container state, health, and memory usage. It does not show a line-by-line Compose diff. Deployments validate Compose, start containers, and wait for health checks. App deployment stops the running app containers, runs Medusa migrations, then starts them, so expect brief downtime.

The foundation opens HTTP/HTTPS and Lightsail browser SSH, enables daily instance snapshots, and attaches a static IP. PostgreSQL uses a named Docker volume and is not exposed publicly. Container memory limits live in each environment configuration. Creating AWS resources incurs charges.

## Before the first app deployment

The `nati_store` repository still needs production backend and storefront images. The backend image must run Medusa on port 9000, support Node's `fetch` for the health check, and contain `/server/apps/backend` with `pnpm medusa db:migrate`. The storefront image must serve HTTP on port 8000 and support Node's `fetch`. Build it with the target public API URL and publishable key. Set both image references and domains in the environment configuration.

Point both domains at the Lightsail static IP for Caddy HTTPS. Verify certificates and application health after deployment. Instance snapshots are enabled, but a PostgreSQL backup and restore procedure is still needed; test a restore before treating the database as durable production data.
